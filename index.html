03 / How I think

Good judgment is part
of the deliverable.

The questions I bring to a project are often as useful as the code. Open a topic to see how I approach the decision.

AI SYSTEMS

What happens when the agent gets it wrong?

Start with the consequences of a failed action. Decide which operations need approval, which can be retried safely, and when the system should hand control to a person.

Then test tool failures, incomplete context, and unexpected inputs alongside the happy path.

The decision this supports

Where automation is useful, and where human control must remain.

DISTRIBUTED SYSTEMS

Which constraint are we actually optimizing?

Average throughput hides a lot. Start with the workload shape, data model, tail latency, failure behavior, and operating cost.

Use a representative test to compare architecture choices. A result without its assumptions is a poor basis for a production decision.

The decision this supports

What to change first, and what evidence would justify the investment.

TECHNICAL EVALUATIONS

What would make this pilot a “yes”?

Agree on the buyer’s requirements, the acceptance criteria, and the people who will judge the result before building the demo.

Keep the evaluation focused on a real workflow and finish with a clear account of what passed, what did not, and what remains to be proven.

The decision this supports

Whether to proceed, change the scope, or stop with useful evidence.
